Part 1

OS Fundamentals, System Calls, Processes & Threads (Direct TPSC PYQ Focus)

10 One-Liners
  • ⚡[TPSC PYQ 2025] The primary purpose of an Operating System is to manage hardware resources (CPU, Memory, I/O, Files) and provide an interface/environment for executing user programs.
  • ⚡[TPSC PYQ 2025] Core OS functions are Memory Management, Process/Task Scheduling, File Management, and I/O Device Management ('Data encryption' is NOT a core OS kernel function).
  • ⚡[TPSC PYQ 2025] UNIX (and Linux/Multics) is a classic example of a Multi-user, Time-Sharing Operating System; MS-DOS is a single-user, single-tasking OS.
  • ⚡[TPSC PYQ 2025] QNX (and VxWorks, FreeRTOS, RTLinux) is a Real-Time Operating System (RTOS) guaranteeing deterministic deadlines.
  • ⚡[TPSC PYQ 2025] The Process Scheduler allocates CPU resources and controls the execution order of processes in an OS.
  • ⚡A System Call (`fork()`, `exec()`, `wait()`, `open()`, `read()`) transitions the CPU from User Mode (Bit = 1) to Kernel/Supervisor Mode (Bit = 0) via a software interrupt (trap).
  • ⚡`fork()` creates a child process; calling `fork()` n times in sequence spawns 2^n total processes and (2^n - 1) new child processes (`fork()` returns 0 to child and child PID to parent).
  • ⚡Process Control Block (PCB) stores PID, Process State (New, Ready, Running, Waiting/Blocked, Terminated), Program Counter, CPU Registers, Memory Pointers, and Open File Descriptors.
  • ⚡Long-Term Scheduler (Job Scheduler) controls the Degree of Multiprogramming; Medium-Term Scheduler performs Swapping (Suspend/Resume); Short-Term Scheduler (CPU Dispatcher) selects from Ready Queue.
  • ⚡Threads within the same process SHARE Code, Data, Heap, and Open Files, but each thread has its OWN private Stack, Program Counter (PC), and Register Set.
Part 2

CPU Scheduling, Process Synchronization & Deadlocks (Direct TPSC PYQ Focus)

13 One-Liners
  • ⚡[TPSC PYQ 2025] In process scheduling, FIFO stands for First In, First Out (also called FCFS — First-Come, First-Served).
  • ⚡Scheduling Equations: Turnaround Time (TAT) = Completion Time (CT) - Arrival Time (AT); Waiting Time (WT) = TAT - Burst Time (BT).
  • ⚡FCFS is non-preemptive and suffers from the Convoy Effect (short processes stuck behind a long CPU-bound process).
  • ⚡SJF (Shortest Job First) / SRTF (Shortest Remaining Time First — preemptive SJF) gives the provably MINIMUM average waiting time, but can cause Starvation of long jobs.
  • ⚡Priority Scheduling can cause indefinite blocking (Starvation) of low-priority processes; solved by Aging (gradually increasing priority of waiting processes).
  • ⚡Round Robin (RR) is designed for Time-Sharing systems using a fixed Time Quantum q (if q → ∞, RR degenerates into FCFS; if q is too small, context-switch overhead dominates).
  • ⚡[TPSC PYQ 2025] Semaphore (introduced by Dijkstra) is a process synchronization mechanism using atomic `wait()/P()` and `signal()/V()` operations to solve Critical Section race conditions.
  • ⚡Critical Section 3 Mandatory Requirements: (1) Mutual Exclusion, (2) Progress, and (3) Bounded Waiting.
  • ⚡[TPSC PYQ 2025] Deadlock is a state where a set of processes are blocked forever because each process holds a resource and waits for another resource held by another process in the same set.
  • ⚡Coffman's 4 Necessary Conditions for Deadlock: (1) Mutual Exclusion, (2) Hold and Wait, (3) No Preemption, and (4) Circular Wait.
  • ⚡[TPSC PYQ 2025] Deadlock handling methods include Resource Allocation Graph (RAG), Locking/Ordering mechanisms (Deadlock Prevention), Banker's Algorithm (Deadlock Avoidance, O(m·n²)), and Deadlock Detection & Recovery.
  • ⚡In a Resource Allocation Graph (RAG): If every resource has only a SINGLE instance, a cycle is both necessary and sufficient for deadlock; if multiple instances exist, a cycle is necessary but NOT sufficient.
  • ⚡Minimum resources R required so that n processes (each needing max k_i resources) NEVER deadlock: R ≥ Σ(k_i - 1) + 1.
Part 3

Memory Management, Virtual Memory, Page Replacement & Disk Scheduling (TPSC PYQ Focus)

8 One-Liners
  • ⚡Contiguous Allocation: First-Fit (fastest), Best-Fit (leaves tiny unusable holes), Worst-Fit — all suffer from External Fragmentation (solved by Compaction or Non-contiguous Paging).
  • ⚡Paging divides logical memory into fixed-size Pages and physical memory into equal-sized Frames; eliminates External Fragmentation completely, but suffers from minor Internal Fragmentation in the last page.
  • ⚡With Page Table in main memory (access time m) and TLB cache (access time c, hit ratio α), Effective Access Time EAT = α(c + m) + (1 - α)(c + 2m).
  • ⚡[TPSC PYQ 2024] In a 4-frame FIFO page replacement system accessing 100 distinct pages 1..100 and then 100..1 in reverse order: first pass causes 100 faults (frames hold 97,98,99,100); reverse pass gets 4 hits on 100,99,98,97 and 96 faults on 96..1 -> Total = 196 Page Faults!
  • ⚡FIFO Page Replacement suffers from Belady's Anomaly (increasing the number of page frames can increase page faults, e.g., reference string 1,2,3,4,1,2,5,1,2,3,4,5 with 3 vs 4 frames).
  • ⚡LRU (Least Recently Used) and Optimal (OPT / Belady's MIN) are Stack Algorithms and NEVER suffer from Belady's Anomaly; Optimal has the lowest possible page fault rate.
  • ⚡Thrashing occurs when a process spends more time paging (swapping pages in and out) than executing instructions due to insufficient frames; cured by Working-Set Model or Page-Fault Frequency (PFF).
  • ⚡Disk Scheduling Algorithms: FCFS, SSTF (Shortest Seek Time First — greedily picks nearest cylinder, may cause starvation), SCAN (Elevator — moves to disk end then reverses), C-SCAN (uniform wait time), and LOOK / C-LOOK.
